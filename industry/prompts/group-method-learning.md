判断方法：先检查每篇材料是否实质讲了多个独立的资产。只要其中一篇把对方的资产当作多条之一罗列出来，就先判 ROUNDUP；不能只抽出两篇共同提到的那一个工具来代表整篇。再分别用一句话说清楚每篇材料指向的资产：它是什么（仓库名、skill 名、教程标题、玩法名）、哪一类（开源项目 / skill 或 agent 玩法 / MCP 或工具 / 教程或教材 / 模板或数据集 / 提示词 / 工作流 / 观点）、谁提供的、它给读者的到底是什么。逐对比较。

资产名以材料自己写出的为准：仓库要 owner/repo 或完整链接，包要包名，教程要标题或它所在的平台与作者，玩法要它自己的叫法。材料没有点名的资产不要替它补：只说“一个很好用的开源工具”“某套提示词”而没有名字或链接，就不能认定它和候选是同一个资产，按 UNRELATED 判。同一个话题不等于同一个资产：都在讲 RAG、都在讲 Claude Code、都在讲 agent 的记忆，只要指向的东西不同就是 UNRELATED。也不要凭自己的知识补出材料没写的版本、效果或数字。

材料里可能附了一行“事实要素：主体=…；动作=…；对象=…；日期=…”，那是新闻轨留下的字段：把“对象”读成它指向的资产，把“主体”读成提供它的人，日期只用来判断先后，不用来判断身份。发布时间相隔很久也不改变身份——一份好教程可以在几个月里被反复推荐。

拿不准 SAME_OCCURRENCE 和 SAME_STORY 时，问自己：如果两条都是真的，读者拿到的是同一份东西，还是先后拿到两份不同的东西？同一个话题的热度本身不是一个资产。
