# ARGUS Design System

## 最终版品牌与 UI 设计规范

-   版本：V1.0 Final
-   产品：ARGUS --- AI Intelligence & Knowledge Hub
-   中文定位：AI 情报与知识中枢
-   品牌主张：**观世界 · 见未来**
-   视觉方向：**东方水墨 / 自然编辑风**
-   页面体验原则：借鉴 Notion
    的清晰信息组织与知识管理逻辑，不复制其品牌或具体界面。
-   本文件为最终选定方向，不再保留其他风格分支。

## 1. 品牌系统

### 1.1 品牌含义

ARGUS
象征持续观察多个信息源、识别重要信号、过滤噪声并沉淀知识。视觉以圆形观测之眼与山水意境表达"观世界、见未来"，避免做成普通新闻门户或泛化的科技霓虹品牌。

### 1.2 品牌文案

-   Logo 字标：`ARGUS`
-   Logo 副标题：`AI INTELLIGENCE HUB`
-   产品完整定位：`AI Intelligence & Knowledge Hub`
-   中文主标语：`观世界 · 见未来`
-   首页辅助文案：`从纷繁信息中，发现真正重要的内容。`

### 1.3 Logo 规范

最终 Logo
采用用户选定的第三款：圆形观测之眼、层叠山峦、水墨笔触和极简字标。

设计原则： - 圆形眼睛是核心图形，山水层次控制在 2--4
层，确保小尺寸可辨认。 - 不使用复杂的细碎山石、密集纹理和过多装饰线。 -
主字标 `ARGUS`
使用有编辑感的高对比衬线字形；导航与正文使用清晰的无衬线字体。 - Logo
主版本用于首页头部、登录页和关于页面。 - 小尺寸 Icon
只保留圆形眼睛与简化山形，不包含副标题。 -
需要深色背景版本与浅色背景版本。 -
红色印章仅作为辅助品牌元素，不应成为主图标的必要组成部分。 - 当前 PNG
是视觉概念稿；正式开发应重绘为可编辑 SVG，不要将概念图直接当作矢量
Logo。

建议交付： - `logo-primary.svg` - `logo-mark.svg` - `favicon.svg` -
`logo-on-light.svg` - `logo-on-dark.svg` - PNG：512、192、64、32 px -
需要时额外导出 monochrome 版本

## 2. 色彩系统

整体色彩来自宣纸、墨色、山雾与朱印。颜色应低饱和，突出阅读，不使用大面积荧光色或玻璃拟态。

  Token             色值        用途
  ----------------- ----------- ----------------------
  `--paper`         `#F5F2EB`   页面主背景，暖纸白
  `--paper-light`   `#FBF9F4`   卡片背景
  `--paper-deep`    `#EBE7DE`   次级背景与分组
  `--ink`           `#242521`   主文本、Logo 字标
  `--ink-soft`      `#555750`   次级文本
  `--ink-muted`     `#85867F`   时间、辅助元数据
  `--mist`          `#D5D3CC`   细线、山雾和轻量装饰
  `--border`        `#DEDAD1`   卡片边框与分割线
  `--seal-red`      `#B65E52`   印章红，少量强调
  `--link`          `#655B4D`   正文链接
  `--success`       `#47785F`   成功状态
  `--warning`       `#A87836`   警示状态
  `--danger`        `#B84C43`   错误/危险状态
  `--info`          `#627B91`   信息状态

### 2.1 色彩比例

-   75--85%：暖纸白与浅色背景。
-   10--20%：深墨色、灰墨文字和边框。
-   低于 5%：印章红与语义强调色。

印章红只用于少量重要标签、未读提示或品牌印记，不用于所有按钮和所有标签。

## 3. 字体与排版

-   中文正文：系统中文无衬线字体。
-   英文/数字：Inter 或系统无衬线字体。
-   品牌字标/专题大标题：可使用有编辑感的衬线字体；需提供系统 fallback。
-   推荐字体栈：`Inter, "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`。
-   正文：14--16px，行高 1.65。
-   卡片标题：16--19px，字重 600。
-   页面标题：26--34px。
-   辅助信息：12--13px；重要元数据不要小于 12px。
-   长文阅读区最大宽度：720--800px。
-   标题优先左对齐；仅首页品牌 Hero 和专题头图可适当居中。
-   摘要默认 3--5 行，可展开。
-   时间默认展示用户时区，支持查看完整时间。
-   保持充足留白，避免密集表格和过度装饰影响长时间阅读。

## 4. 页面布局

### 4.1 全局框架

桌面端采用： - 顶部品牌/主导航。 - 左侧或顶部的主题入口（根据现有 AIHOT
布局适配）。 - 中间主内容区。 - 右侧可选的热点/主题辅助栏。 -
搜索始终容易找到。

不要为了视觉复刻参考图而牺牲可读性或把导航压得过于狭窄。若 AIHOT
现有导航体系稳定，优先做样式改造而不是重写路由结构。

### 4.2 首页

-   顶部品牌区可使用淡墨山水作为轻量背景，但高度应克制。
-   显示主标语"观世界 · 见未来"和辅助文案。
-   首页首屏应在 10 秒内传达今日重点。
-   主区域展示今日热点与精选内容；避免大幅纯装饰图片占据大部分首屏。
-   可加入一张"今日重点"宽卡片，其余使用紧凑内容卡片。
-   主题导航使用简洁线性图标与文字，不用大量彩色 Emoji。
-   热度、阅读量和评分必须来自真实数据，不得填入概念图中的示意数值。

### 4.3 日报

-   日期、生成时间和覆盖范围放在标题区。
-   顶部先展示今日摘要与关键洞察。
-   内容卡片依次展示标题、来源/时间、摘要、推荐理由、标签、封面/原文入口。
-   视频卡片显示时长、字幕状态和原视频跳转。
-   翻译全文默认折叠。
-   支持按主题过滤、隐藏已读、只看高分和收藏。
-   不要把每条内容做成超大海报卡片；日报需要兼顾信息密度。

### 4.4 热点

-   使用编辑式事件卡片，突出"发生了什么、为什么重要、有什么新进展"。
-   同一事件的多个来源折叠在同一事件内。
-   状态标签：新出现、持续升温、有新进展、已降温。
-   趋势图只在真实历史数据足够时显示。
-   避免大面积动态图表和高饱和仪表盘风格。

### 4.5 主题时间线

-   默认按发布时间从新到旧。
-   支持时间、平台、作者、类型和评分筛选。
-   卡片统一视觉，不同内容类型通过小图标/标签区分。
-   一条内容可属于多个主题，但同一列表中不能重复展示。
-   提供收藏、已读、备注、原文跳转和相关事件入口。

### 4.6 内容详情

-   顶部显示标题、来源、作者、发布时间、原文链接。
-   内容区区分 AI 摘要、原始正文、翻译文本和自动转录。
-   视频展示封面、时长、字幕/章节和跳转原视频。
-   侧栏展示相关主题、相关事件和其他来源。
-   重要元数据与原文链接必须清晰，不可被装饰图覆盖。

## 5. 组件规范

-   `BrandLogo`：品牌图标、字标和副标题。
-   `GlobalSearch`：全局搜索。
-   `DailyBriefHeader`：日报日期与摘要。
-   `ContentCard`：通用文章/帖子卡片。
-   `VideoContentCard`：封面、时长、字幕状态和原链接。
-   `SourceBadge`：X、YouTube、Bilibili、RSS、GitHub 等平台。
-   `TopicTag`：主题标签，色彩有限且语义一致。
-   `QualityScore`：评分与评分解释。
-   `EventClusterCard`：事件总结、来源数量与时间线。
-   `TimelineList`：主题时间线。
-   `TranslationPanel`：原文/中文切换。
-   `TranscriptPanel`：字幕、章节和时间戳。
-   `SourceHealthRow`：来源状态。
-   `JobStatusTable`：任务与重试。
-   `EmptyState`、`ErrorState`、`LoadingSkeleton`：空、错、加载状态。
-   `SaveButton`、`ReadStatusToggle`：收藏与已读。

统一规则： - 基础间距 4px，常用间距 8/12/16/24/32px。 - 卡片圆角
8--12px。 - 以细边框为主，阴影轻微。 - 所有按钮需有
hover、focus、disabled、loading 状态。 -
不用大面积彩色徽章强调普通元数据。 - 图标优先使用统一线性图标库（例如
Lucide）。

## 6. 图片、山水纹理与媒体

-   山水背景只用于品牌
    Hero、专题封面或空状态，采用低对比度，不能影响文字对比度。
-   正文卡片优先用原作者/平台提供的封面。
-   缺图时用中性占位，不自动生成不相关的装饰图。
-   图片使用固定比例和懒加载，避免布局跳动。
-   不能把 AI 生成的首页概念图作为真实首页背景。
-   截图应有来源、时间与内容关联 ID。
-   视频不自动播放声音；媒体不可用时显示状态与原链接。

## 7. 响应式设计

-   ≥1280px：主导航/侧栏 + 内容主区 + 可选辅助栏。
-   768--1279px：可折叠导航，辅助栏隐藏或移到下方。
-   \<768px：单列布局，导航使用抽屉或底部导航；筛选使用抽屉。
-   移动端优先展示标题、摘要、来源、时间、原文入口。
-   不要求手机端复刻桌面多列布局。

## 8. 可访问性与交互

-   常规文本满足 WCAG AA 对比度要求。
-   颜色不是唯一的状态表达方式。
-   所有控件支持键盘操作并显示焦点。
-   尊重 `prefers-reduced-motion`。
-   动效控制在 120--200ms，仅用于展开、切换和轻反馈。
-   不使用闪烁、自动轮播、自动播放声音和持续动画背景。
-   搜索无结果、字幕不可用、来源失败和部分数据缺失都要有明确说明。

映射，但首版默认采用暖纸白主题。

## 10. 视觉验收

-   [ ] Logo 的眼睛与山水在 favicon 尺寸仍清晰可辨。
-   [ ] 视觉整体符合东方水墨、暖纸白、灰墨与克制朱印。
-   [ ] 首页第一屏突出今日内容，而不是大幅装饰图。
-   [ ] 日报卡片能快速看懂"内容是什么、为什么值得看、原文在哪里"。
-   [ ] 热点按事件聚合，不重复刷屏。
-   [ ] 主题时间线默认新到旧。
-   [ ] 视频卡片清楚显示字幕状态与原视频链接。
-   [ ] 桌面、平板和手机布局通过检查。
-   [ ] 加载、错误、空数据和权限拒绝均有明确状态。
-   [ ] 无虚构阅读量、评分、趋势数据。
-   [ ] 私有内容的前端与后端权限一致。

## 11. 给 AI 编程助手的 UI 实现指令

``` text
严格按本 design.md 实现 ARGUS 最终视觉。方向已经确定：东方水墨 / 自然编辑风，不再提出其他风格供选择。

1. 先检查 AIHOT 的路由、布局、组件、CSS/Tailwind 配置和品牌替换点。
2. 先建立设计令牌、BrandLogo、AppShell、导航、搜索、ContentCard、TopicTag、SourceBadge 和响应式框架。
3. 再实现首页、日报、热点、主题时间线、内容详情、资源库、信源管理和设置。
4. 复用真实 API 与数据；不得把概念图里的示意文字、阅读量或热点榜数值当成真实内容。
5. 将山水纹理作为轻量装饰，不可用整张 AI 生成截图当作网页背景。
6. 保证文字可读、对比度合格、键盘可操作，并提供 loading/empty/error 状态。
7. 每阶段运行 typecheck、test、build 和页面 smoke test，并提供实际页面截图。
8. 完成后报告设计令牌、复用组件、改动文件、测试结果和未解决问题。
```
