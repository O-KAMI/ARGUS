## 一、审计意见

**当前版本需要先修复私有访问控制，再作为对外可达的私有站部署。** 本次用当前构建复现了未登录读取私有页面及其导航数据的路径。同一轮检查也发现，采集、归并和榜单有几处会让系统在漏数据、合错事实或只读到部分结果时，仍给出看似正常的页面。这些问题比扩容或换模型更直接地影响长期使用。

**建议保留 Web、API、Worker 三进程、PostgreSQL、pg-boss 以及发布读取层。** 本地库约 259 MB，主要问题出在各阶段对“处理成功”和“内容相同”的定义。保留学习精选、行业镜像和 GitHub 榜单的不同口径。修复私有边界和数据一致性后，再用本人的标注改进筛选和阅读效率。

| 从读者目标出发 | 系统必须保证 | 当前判断 |
|---|---|---|
| 只有本人能读 | 同一资源的不同 URL 写法执行同一授权 | **未满足，已复现** |
| 关注的人发布干货能被发现 | 游标只覆盖已经处理或按明确规则排除的范围 | **首次 X 分页存在中间缺口** |
| 高价值内容能进精选 | 模型能看到决定价值的证据，评测重现生产决策 | **图文证据与门槛评测有偏差，实际召回率未知** |
| 同一消息只读一次，新进展仍能看到 | 材料、资产、事实、事件四种身份分开 | **同一资产会直接决定同一事实** |
| 快速知道现在值得看什么 | 当前、部分、过期、空榜对用户有不同含义 | **镜像与 GitHub 均有状态混淆** |
| 长期可用、可恢复 | 可识别数据停更，可验证备份恢复，前端读到有效快照 | **数据库结构具备基础，当前库缺少自动备份成功记录** |

## 三、架构、安全、采集与判断

### 1. P0 · 未登录读者可绕过 Web 私有门禁【隔离环境复现】

Web 用原始请求路径匹配公开前缀。后续页面路由又会规范化点段，两处看到的路径不同。SSR 在服务端携带内部令牌，导致一个本意只向静态资源或登录页开放的请求最终可以得到私有内容。测试上游拒绝无内部令牌的请求，登录检查始终返回 401。

| 未携带 Cookie 的原始请求 | 状态 | 响应含仅在受保护 API 中提供的标记 |
|---|---:|---|
| 正常热点路径 | 302 | 否 |
| 通过资源前缀和编码点段抵达热点页 | 200 | **是** |
| 通过登录前缀和点段抵达热点导航数据 | 200 | **是** |

**处置。** 受影响版本如对公网可达，先限制入口。修复时让授权、静态文件查找、API 转发和 SSR 共用同一个路径判定。对有歧义的编码、分隔符、点段及异常请求目标在路由前拒绝。静态豁免仅用于实际匹配的构建资产，未匹配不能回落到带内部令牌的 SSR。API 自身继续检查会话或受信任的内部令牌。私有开关应只接受显式 true/false 或缺省值，拼写错误启动失败；现有布尔解析把其他非空值解释为 false。修复后验证合法资源、登录、退出、授权用户、匿名拒绝、HTML 和导航数据，并在实际代理拓扑复测。

可运行的 [本地复现程序](reproduce-private-read.mjs) 使用随机测试令牌，不连接业务库。当前返回码 1 表示读出了测试标记。相关代码在 [Web 路径授权与分派](../../../apps/web/server.ts) 第 29、251–293 行和 [SSR 请求头](../../../apps/web/app/lib/api.server.ts) 第 10–12 行。现有日志不足以从这次复现追溯公网访问。

### 2. P1 · 私有入口同时破坏了合法的机器接入和 CI 验收【复现＋源码确认】

- Web 在转发 API 前先检查读者会话。测试以有效测试 Bearer 提交 `POST /api/ingest/items`，得到 302，后端 ingest handler 调用次数为 0。API 原本要求专用 Bearer 并独立限流。应将明确由 API 自行鉴权的写入路径直接转发，同时维持私有读接口的会话认证。验收涵盖正确 Bearer、错误 Bearer、匿名读者和已登录用户。[Web 入口](../../../apps/web/server.ts) · [推送接口](../../../apps/api/src/routes/ingest.ts)
- 普通 CI smoke 没有设置 `PRIVATE_ACCESS` 或 `INTERNAL_TOKEN`。在同样的缺省配置下，实际调用 `buildApp()` 会因缺内部令牌拒绝启动。Docker CI 用初始化脚本开启私有访问，却执行匿名 smoke，脚本要求页面和机器出口返回 200。代码路径已确认，未声称远端 CI 的某次运行状态。将 CI 拆成显式公开模式的全出口 smoke，以及私有模式的匿名拒绝和带测试会话 smoke。增加 GitHub 模块路由。生产默认值继续为私有。[CI 定义](../../../.github/workflows/check.yml) · [Smoke 脚本](../../../scripts/smoke.ts) · [API 私有门禁](../../../apps/api/src/private.ts)

### 3. P1 · 新 X 源的首次入库与分页游标不一致【本地假服务复现】

四页、每页 20 条的时间线上，首次读取前三页 60 条，入库时只保留前 30 条，保存的 backlog 却已指向第四页。下一次抓取可写入更旧的第 61–80 条，第 31–60 条留在缺口中。显式限制首次导入数量是合理策略，缺陷是跳过中段却继续向更早的历史翻页。已有运行的实际漏量无法从本地库反推。

**修复。** 以“首次历史总上限 30，可配置”为默认口径，区分追新游标与历史回填边界；达到上限后明确停止历史链，记录主动排除的范围。需要分批导入时，续点跟随最后持久化的边界。只有已提交或明确排除的数据才算完成。验收用四页夹具覆盖首轮、次轮、重启及重复输入，不能既跳过中段又收更老的记录。旧账号先只读列出可判定的缺口；付费补采按账号与时间窗口估价。

RSS 已对首次导入延后确认 validator；消息幂等、材料修订、失败游标和付费回执已有机制。扩展现有抓取记录，区分发现、实际写入、重复、主动排除、尚待补采；监控同时展示“最后运行”和“最近原文时间”，避免把账号沉默误报为故障。[采集与游标](../../../packages/backend/src/sources/collect.ts) 第 336–361、387–395 行 · [X 读取器](../../../packages/backend/src/sources/x.ts)

### 4. P1 · 改变学习门槛时，评测无法预测上线结果【纯函数反例】

学习轨采用 hit=90、edge=60、miss=20，仅当首评分数恰好等于门槛才调用第二次。新闻轨走连续分数双评。两种价值标准应继续分开。问题在于离线脚本按当前门槛取得一组分数，再用这组分数扫描其他门槛。

例如当前门槛 60，先 edge 后 hit，得到 [60,90]。脚本扫门槛 74 时用平均 75，判入选；实际门槛改为 74 时，首轮 60 不触发复判，结果是拒绝。当前门槛调整为 90 时，另一些案例会缺少上线实际需要的第二意见。[评分停止规则](../../../packages/backend/src/editorial/analyze.ts) 第 77 行 · [评测扫描](../../../scripts/eval-selection.ts) 第 225–256 行

**修复。** 评测与生产共享停止及判定函数，评测保留逐次原始档位，每个候选门槛重放真实决策。缺第二次答案时记录证据不足和覆盖率，不把缺失当低分或成功。分别核算离线取样费用和上线预期调用量。金标出现前维持 60；发布比较以本人认可的干货为正例，优先看漏选、再比较每天多读多少噪声和付费调用量。

### 5. P1 · 评分可用的证据与目标内容形态不一致【源码确认，损失率未知】

学习提示词承认“一张截图加一句话”的教程，但预判、学习评分和结构化主要消费文本，图片在分数确定后才进入内容理解。评分通用 user 消息还要求只输出 `attentionScore`，学习分支实际要求 `level,kinds`。截图中有步骤而正文只有“配置如下”时，判分阶段拿不到核心证据。现有结构无法证明漏掉了多少条。[评分输入与执行顺序](../../../packages/backend/src/editorial/analyze.ts) 第 146、336、398、415、560 行 · [学习轨标准](../../../industry/prompts/selection-score-learning.md)

**修复。** 先按轨生成一致的输出说明。对学习轨的短文本加图材料，在预筛拒绝前提供受预算控制的视觉证据，按修订缓存，保留文字来源；视觉不可用时标为“证据不足、可回看”，再决定是否补判。先影子评测，不默认给所有帖子增加模型调用。

**校准。** 复用已有盲标工作表，覆盖精选、边缘、拒绝、预筛阻断和图文内容。以时间和事实/资产隔离开发与留出集；按层报告，若估计总体指标则按各层实际比例加权。人工标注现有入口会同时更改线上精选，初次实验应在副本或离线金标集执行。比较“每百条有用内容漏掉几条、每日报入多少无用内容、每识别一条有用内容的调用成本”，附样本量及区间。只有漏选没有恶化且代价可接受，才采用新策略。[金标工作表](../../../scripts/gold-worksheet.ts) · [标注写入](../../../packages/backend/src/admin/labeling.ts)

### 6. P1 · 相同资产键被当成相同事实【源码确认＋键碰撞复现】

材料身份解决“是不是这条帖子”，资产解决“在谈哪个项目”，事实解决“具体发生了什么”，事件组织相关事实。现在同一资产跨时间召回已有 fact 后，可以绕过关系判断直接记录 `SAME_OCCURRENCE`。已有精选代表时，还可能跳过增量价值判断并强制赋予 `addsValue=true`。同一仓库的新版本或新漏洞可能被并进旧事实；重复推荐则可能被当作有新增价值。日报按 fact 回看过去七天，这使错并能够传播到日报。该路径成立，但存量错并率需要人工判例。[资产召回](../../../packages/backend/src/events/recall.ts) 第 280 行 · [归并决策](../../../packages/backend/src/events/group.ts) 第 346、408、448 行 · [日报记忆](../../../packages/backend/src/reports/edition.ts)

- **解析。** 已复现同机构两个不同 Hugging Face dataset 都被识别为 `hf:datasets/acme`，且 `notgithub.com/acme/repo` 也会命中 GitHub 键。应解析 URL 后精确匹配主机与资源路径，将模型、dataset、space 分开。[资产键解析](../../../packages/backend/src/lib/asset-key.ts) 第 32–41 行
- **修订。** 正文移除链接时资产更新会沿用旧值；补抓正文与已有事实成员的重判也不一定重新推导资产及归属。应在统一修订入口区分“字段未提供”与“完整内容已删除该资产”，变更时重评自动归属，保留人工决定。[材料修订](../../../packages/backend/src/content/materials.ts) 第 338、382 行 · [补正文](../../../packages/backend/src/content/extract.ts) · [已有归属](../../../packages/backend/src/events/group.ts) 第 393–402 行
- **判定。** 资产键用于关联、界面折叠和候选召回；只有发生的动作、对象和版本/时间等证据一致才归入同一事实。相同事实也要独立判断报道是否有新增阅读价值。以重复推荐、新版本、同仓库事故、对照实测、链接删除作回归样本。先输出旧键→新键、成员差异、受影响榜单/日报与调用预算；在副本回放，只重算已确认的自动成员。历史刊和人工覆盖保持可追溯。

## 四、镜像、榜单与出刊

### 7. P1 · 镜像读取成功、应用成功、内容版本是三件事【源码确认】

| 触发条件 | 现在会发生什么 | 修复与验收 |
|---|---|---|
| 原文 headline 不变，上游改中文标题、摘要、分类或评分 | 只有材料 created/revised 才写 rule analysis，且同修订已有分析就直接返回，publication 可继续展示旧判断 | 给继承编辑结果独立指纹，变更时事务内更新继承判断和发布投影；不发送推送、不调用模型。同一输入重放幂等 |
| 完整窗口中一条事务暂时失败，上游随后返回 304 | 单条异常被计为 skipped，但窗口 ETag 仍可提交，失败项长时间不再处理 | 将永久业务拒绝与可重试错误分开；有未应用项就不确认该版本，或持久化重试项。上游始终不变也要自动补齐 |
| 精选窗口有多页，第一页内容未变而后页有更正 | 客户端用第一页的 ETag 判断整个窗口 unchanged，后页不会再读。本仓同款 v1 按当页响应生成 ETag，真实上游是否额外承诺全窗版本未验证 | 多页窗口须保存各页校验状态或定期无条件完整对账；单页可沿用条件请求。用“第一页 304、第二页摘要变化”验证不能无限期漏更新 |
| 200 响应丢失有效榜单，保留旧 answer | 同时更新 lastOkAt，会把旧快照的验证时间显示为“刚成功” | 分开记录请求时间、最近有效验证、内容生成/应用时间。畸形响应不刷新有效性；304 可确认未变，但不能冒充内容新生成 |
| 上游条目退出精选窗口 | 仅靠本地首次发现后 7 天清理，不能区分上游明确撤选、分页未见、自然滑出 | 完整窗口才对账。明确撤选与自然过期分别处理，partial 时不可按缺席撤稿。保留“本地发现后滚动留存”的既定语义，并在界面说明 |

### 8. P1 · GitHub 部分结果可以覆盖榜单，关闭采集仍能执行手工刷新【源码确认，含本地数据佐证】

### 9. 热点、日报与长周期知识

- **热点。** 本站热度按 48 小时窗口的独立参与者及时间衰减计算，至少两位参与者、其中至少一位 editorial；有镜像榜时读取镜像并展示上游排名。两者衡量讨论热度，不应拿它们替代学习价值评分。保留撤回后重新验证代表报道的读取规则。增加运营对照：热榜每条来自哪个榜、哪些账号按同一主体合并、补采和暂停是否让趋势不可比。[计算](../../../packages/backend/src/events/hot.ts) · [发布选择](../../../packages/backend/src/publication/hot.ts)
- **日报。** 零精选与上游没有任何判定是不同情况，代码已有区分。不足之处是自动补刊从最早已有刊开始；当首刊为 11-01 时，10-30/31 的缺口不会再被该循环发现。建立明确的启刊日与逐日出刊状态，区分“未启刊、无入选、上游未就绪、已发布”，故障需看到具体失败原因和补刊窗口。已有刊不静默重写。10-30 涉及历史窗口，先给预览；当前业务库不能证明当天本应有多少条。周月报同时展示覆盖了多少期、缺哪几期。[出刊与补刊](../../../packages/backend/src/reports/compose.ts) 第 95、305–333 行
- **知识沉淀。** 镜像按既定裁定不进事件图、不进日报，并按本地发现时间滚动保留。浏览器收藏有本地备份导入导出，已下架内容有提示。建议在镜像详情说明留存期与原文地址，在收藏页对过期条目优先提供可用的原文出口；长期保存聚焦自有学习材料和个人笔记，无须把整个镜像纳入永久全文库。[产品裁定](../../../项目地图.md) · [收藏行为](../../../apps/web/app/routes/starred.tsx)

## 六、实施顺序和发布条件

| 顺序 | 可独立交付的改动 | 发布条件 |
|---|---|---|
| **A · 私有边界与 CI** | 修 Web 授权、静态白名单、机器推送和 smoke；清理歧义配置 | 原始/编码路径、HTML、导航数据、私有 API、RSS、媒体均不能匿名读出测试标记。合法登录和 Bearer 推送可用。普通和 Compose 两条 CI 都覆盖有权/无权用例 |
| **B · 采集与快照** | X 首次历史边界，镜像编辑指纹与 ETag 提交，GitHub 总开关、完整/部分/空榜及元数据更新 | 四页假源无中段缺口；单项事务故障后能补齐；partial 无法盖掉完整榜；成功空榜有时间且为零条；禁用后对外请求为零 |
| **C · 资产、事实与学习质量** | 分离资产关联与事实判定，修键解析和修订失效；修评测重放、学习输入和图文证据 | 同仓库同事实可合，新版本与事故可分，纯重复无新增值。门槛 60/74/90 的离线结果逐例等于生产规则。先做无付费回放和盲标，再按证据决定视觉调用范围与阈值 |
| **D · 阅读体验、出刊与恢复** | 恢复桌面筛选、修滚动遮挡和 GitHub 标题/状态、缩短手机首屏、可见的补刊与恢复状态 | 七页两端无横向溢出；第一条学习标题进入手机首屏；屏幕阅读顺序和键盘可达；故障时仍可读可信快照。日报缺期可解释，隔离恢复通过 |

**兼容与回退。** 保留已有 item/story 公共 ID、URL、筛选参数、外部 API、浏览器收藏及人工覆盖。新状态优先以可空列或模块状态记录增量发布，读取兼容旧快照，旧记录无法证明完整时显示“完整性未知”。先部署兼容读取，再写新状态，最后小批重算。旧迁移不改，数据回填不放进发布迁移。涉及存量归属时先备份、在副本产生差异清单与预算，再按键/事实小批实施；保留每批前后映射，历史出刊单独处理。回退版本不得重新开放有缺陷的 Web 门禁。

**本人需要参与的环节仅是价值判断。** 先用现有样本做一轮盲标，尤其检查预筛拦截、截图教程和“同资产但有新知识”的案例。安全边界、游标与快照一致性都有确定的工程验收标准，可以先行解决。等留出集能衡量漏选和阅读成本后，才有依据决定是否换模型、调分或扩大采集范围。
