## 阅读顺序建议

1. 先读仓库根的 [`项目地图.md`](../../项目地图.md) —— 它是交接与验收上下文（功能逻辑、UI 视觉规范、前后端、坑点、待办、经验总结），并标出了上面每份方案里**已被实测推翻或已被后续裁定覆盖**的段落。
2. 再按需回看具体方案。方案是**当时的意图**，项目地图是**现在的事实**；两者冲突时以项目地图与代码为准。

## 为什么不放设计参考图

交付包里另有 6 张 PNG（品牌识别板、首页视觉参考、Logo 概念稿、图标 sprite、两张山水板，约 11 MB）**刻意不进仓库**：其中「网站首页视觉参考」是第三方站点的截图，公开分发不合适；其余属于过程材料。要看它们的人在本地项目目录的交付包内可以找到（仓库外的同级目录，不进版本库）。

## 新方案的规矩

- 文件名 `argus-<主题>.md`，中文主题名可以，日期写在正文标题下方而不是文件名里。
- 方案落地后**不删不改历史正文**，改为在 `项目地图.md` 对应章节记「实现与原方案的差异」，并回到本表更新「状态」列。
